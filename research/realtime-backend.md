# Realtime backend for the shared Event (ticket 004)

Researched 2026-10-21. Scope: one Event has invited Members, one live Chat, a shared Canvas of separately editable items, Comments, edit history, presence dots, and an Assistant whose reply and Canvas edits reach every Member. The five-day build target and existing Next.js, Convex, and Clerk experience matter more than the maximum theoretical collaboration feature set.

## Recommendation

**Choose Convex + Clerk, with Next.js on Vercel.** A subscribed Convex query can drive both Chat and Canvas; the Agent component can persist throttled reply deltas that every Member subscribes to; Clerk already has a documented App Router integration. This is the shortest supported path to the required demo. [Convex App Router](https://docs.convex.dev/client/nextjs/app-router/), [Agent streaming](https://docs.convex.dev/agents/streaming), [Convex + Clerk](https://docs.convex.dev/auth/clerk), [Vercel package managers](https://vercel.com/docs/package-managers).

**Risks (inference):** presence still needs a heartbeat/TTL component or custom logic; each public function and Agent tool must enforce Event membership; frequent stream writes and image delivery can hit free limits. The PWA share target works only on supported installed PWAs, so a normal in-app paste/upload path remains necessary. [Convex presence pattern](https://stack.convex.dev/presence-with-convex), [Convex authorization](https://docs.convex.dev/auth/overview), [Convex limits](https://docs.convex.dev/production/state/limits), [MDN share target](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Manifest/Reference/share_target).

**Inference, shared data design:** Use an opaque, expiring invite token tied to `eventId`; after Google sign-in, redeem it once in a server-checked operation that creates an `eventMembers(eventId, userId, role)` record. The URL proves invitation only, never ongoing access. Query and write membership on every Event-scoped operation, including upload authorization and Assistant tools. Keep `CanvasItem` at item granularity for last-write-wins v1; add an immutable `itemEdits` row per accepted edit with actor, time, before/after or patch, including Agent edits. Comments are separate item-scoped rows. Transactions or a single mutation should write item + history together. These are design recommendations from the access-control and realtime mechanisms above, not vendor guarantees. [Convex authorization](https://docs.convex.dev/auth/overview), [Firebase rules](https://firebase.google.com/docs/firestore/security/rules-conditions), [Supabase RLS](https://supabase.com/docs/guides/database/postgres/row-level-security).

### Shared AI reply: exact mechanism

- **Convex observation:** A server-side Agent action calls `agent.streamText(ctx, { threadId }, { prompt }, { saveStreamDeltas: { chunking: "line", throttleMs: 1000 } })`. Deltas are saved in batches; all subscribed clients can see them, including clients that reconnect. The Agent tool has `runMutation`, so Canvas changes can be made through a checked mutation; the Agent docs explicitly recommend keeping artifacts in app tables and versioning them. [Streaming](https://docs.convex.dev/agents/streaming), [Agent tools](https://docs.convex.dev/agents/tools). **Inference:** map one Event to one authorized Agent thread; submit a Member message in a mutation, schedule one generation job, and subscribe Members to both persisted messages/deltas and Canvas queries. Set an idempotency key/status per Assistant turn to avoid duplicate jobs; throttle rather than writing each token. A plain HTTP response stream reaches only its requester and does not satisfy the shared Chat requirement. [Streaming](https://docs.convex.dev/agents/streaming).
- **Firebase observation:** Firestore listeners broadcast persisted document changes; Functions/App Hosting/Cloud Run can execute the server AI call. Firestore has 20,000 free writes/day. [Listeners](https://firebase.google.com/docs/firestore/query-data/listen), [Firestore quota](https://firebase.google.com/docs/firestore/pricing), [Cloud Functions HTTP](https://firebase.google.com/docs/functions/http-events). **Inference:** keep a pending Assistant message document, write throttled cumulative text or ordered chunk documents from a server worker, and have every Member listen. One write per model token multiplies write quota and listeners' read cost; write at about 0.5-1 second intervals, then finalize. Protect the trigger from duplicate invocation and validate Event membership before Admin SDK writes. A streamed HTTP response alone reaches only the initiating Member. [Firestore pricing](https://firebase.google.com/docs/firestore/pricing), [server bypass](https://firebase.google.com/docs/firestore/security/rules-query).
- **Supabase observation:** Edge Functions can perform server calls; Broadcast can send to a private Event channel over WebSocket or REST, while Presence uses the same channel. Free Edge workers have a 150-second wall-clock limit and 150-second response idle timeout. Broadcast delivery itself is transient; database Broadcast records are deleted after three days. [Edge limits](https://supabase.com/docs/guides/functions/limits), [Broadcast](https://supabase.com/docs/guides/realtime/broadcast). **Inference:** authenticate the function, insert a durable pending Chat row, send throttled deltas by private Broadcast, and update the row periodically/finally. Rejoining clients fetch the current row; clients de-duplicate deltas by turn/sequence. Alternatively persist chunks as rows and subscribe via Postgres Changes, trading simpler replay for extra database/realtime traffic. Ensure private topic RLS matches Event membership; do not rely on a public channel. [Realtime authorization](https://supabase.com/docs/guides/realtime/authorization), [database changes](https://supabase.com/docs/guides/realtime/subscribing-to-database-changes).

## Stretch: cursors and concurrent editing

**Observation:** Supabase explicitly recommends Broadcast for cursor-frequency traffic rather than Presence `track()`. Convex has a Presence component and a ProseMirror Sync component for Tiptap/BlockNote; ProseMirror Sync uses operational transformation, supports server-side transforms for AI edits, and does **not** itself sync presence/cursors. Its page warns that BlockNote does not currently support React 19 StrictMode. [Supabase Presence](https://supabase.com/docs/guides/realtime/presence), [Convex components](https://www.convex.dev/components), [ProseMirror Sync](https://www.convex.dev/components/prosemirror-sync).

**Observation:** Yjs `y-websocket` carries document updates and cursor awareness but requires a running/persisted WebSocket server. Liveblocks hosts a Yjs provider and room awareness; its Supabase integration mirrors Yjs through throttled webhooks, so Supabase becomes an eventually consistent mirror rather than the editor's live authority. Automerge Repo likewise needs a sync server/network adapter for production; its public community server has no reliability or data-safety guarantee. [Yjs WebSocket](https://docs.yjs.dev/ecosystem/connection-provider/y-websocket), [Liveblocks Yjs](https://liveblocks.io/docs/products/sync/text-editing/yjs), [Liveblocks + Supabase](https://liveblocks.io/docs/integrations/supabase), [Automerge sync](https://automerge.org/docs/tutorial/network-sync/).

**Inference:** keep v1 item-level last-write-wins and an edit log. For a later single rich-text Canvas item, Convex's ProseMirror Sync is the closest integrated route, but test it with the chosen React 19 editor and its auth wrapper first. Firebase/Supabase can use Liveblocks-hosted Yjs or an independently hosted Yjs/Automerge server; these add another realtime authority, permissions, and persistence to operate. Live cursors can ship separately before conflict-free editing, with throttled ephemeral updates. Do not treat simple last-write-wins item updates as conflict-free simultaneous text editing. [ProseMirror Sync](https://www.convex.dev/components/prosemirror-sync), [Yjs WebSocket](https://docs.yjs.dev/ecosystem/connection-provider/y-websocket), [Liveblocks Yjs](https://liveblocks.io/docs/products/sync/text-editing/yjs).

## PWA share target for Event Chat

**Observation, browser matrix:**

| Platform | Receiving a system share into an installed PWA |
| --- | --- |
| Android Chrome | Supported since Chrome 76, with the PWA installed. [Chrome](https://developer.chrome.com/docs/capabilities/web-apis/web-share-target) |
| Desktop Chrome | Supported since Chrome 89 on supported desktop sharing systems; installation and OS share integration are required. [Chrome](https://developer.chrome.com/docs/capabilities/web-apis/web-share-target) |
| Desktop Edge on Windows | Supported for installed PWAs via Windows Share. [Microsoft Edge](https://learn.microsoft.com/en-us/microsoft-edge/progressive-web-apps/how-to/share), [Windows Share](https://learn.microsoft.com/en-us/windows/apps/develop/windows-integration/integrate-sharesheet-receive) |
| iOS Safari | No Web Share Target support; Safari's outgoing `navigator.share()` is a different API. Offer paste/upload inside the app. [MDN share target compatibility](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Manifest/Reference/share_target), [MDN Web Share](https://developer.mozilla.org/en-US/docs/Web/API/Web_Share_API) |

**Observation:** Next.js App Router serves `app/manifest.json` or `app/manifest.ts`. A file-capable target declares `share_target.action`, `method: "POST"`, `enctype: "multipart/form-data"`, and `params` for `title`, `text`, `url`, and accepted `files`. A service worker can intercept the POST, parse `request.formData()`, retain files in Cache/IndexedDB or send them to the server, then redirect/open the app. A server endpoint can also receive the POST; the foreground page cannot read the incoming POST directly. On Android, the `url` field may be empty and the link is often in `text` or `title`. [Next.js manifest](https://nextjs.org/docs/app/api-reference/file-conventions/metadata/manifest), [Chrome share target](https://developer.chrome.com/docs/capabilities/web-apis/web-share-target), [web.dev file handling](https://web.dev/articles/files/receive-shared-files), [MDN manifest](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Manifest/Reference/share_target).

**Inference, Next.js flow:** declare a static `app/manifest.json` with a POST target such as `/share`; register a service worker for multipart/file handling, or implement `app/share/route.ts` for an online server POST and redirect. Keep the received payload as a draft until the Member authenticates and chooses an Event; then insert a Chat message and, if it has an image, upload an Inspiration after validating MIME, size, and Event membership. A service worker is especially useful to avoid losing a file while navigating through sign-in/Event selection. Test the installed PWA and POST behavior on an actual Android device. [Chrome share target](https://developer.chrome.com/docs/capabilities/web-apis/web-share-target), [web.dev](https://web.dev/articles/files/receive-shared-files).

**Observation vs unknown sender payload:** Pinterest documents sharing a Pin/board link to third-party apps and a "Copy link" action. Android supports shared text (`EXTRA_TEXT`) and file/image URIs (`EXTRA_STREAM`), but neither Pinterest nor Instagram publishes a stable contract for the exact fields its Android app passes to a PWA share target. [Pinterest help](https://help.pinterest.com/en/article/send-pins-boards-and-profiles), [Android receiving shares](https://developer.android.com/develop/ui/compose/sharing/receive), [Chrome field caveat](https://developer.chrome.com/docs/capabilities/web-apis/web-share-target). **Inference:** expect a Pinterest link and an Instagram post/reel link as text when those apps expose an external share action; an image may arrive for a downloaded image or a different share action, but must not be assumed. Instrument a temporary local share receiver to inspect `title`, `text`, `url`, file count/type/size from each installed app version on Android. Never rely on scraping an Instagram/Pinterest image from the link for v1. [Pinterest help](https://help.pinterest.com/en/article/send-pins-boards-and-profiles), [Chrome field caveat](https://developer.chrome.com/docs/capabilities/web-apis/web-share-target).
